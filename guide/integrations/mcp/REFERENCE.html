MCP tool reference¶

Start and connect · Workflows

Configuration¶

Setting

Meaning

KANGENGINE_MCP=1

Enable MCP at App.start(); off by default.

KANGENGINE_MCP_PORT

Port for the environment opt-in; default 8765. For serve, use --port.

KANGENGINE_MCP_TOKEN

Supplied credential; otherwise generated at each server start.

KANGENGINE_MCP_TOOLS

Comma-separated tool groups; replaces the defaults.

One active App per process is supported. For multiple Apps, use separate processes and ports: serve --port 8766 or serve --port 0 for an available port.

Tool groups¶

Default groups are scene,camera,capture,recording,profile,docs: 24 tools including engine_status. Without guide files, search_docs and get_doc are omitted at startup, leaving 22 tools; get_api_docs remains available. The optional scenario group adds five tools and requires registered MCP targets for playback. See the Group column below for membership.

KANGENGINE_MCP_TOOLS=scene,camera,capture python -m kangengine.adapters.mcp serve

Unknown or empty group selections fail at startup. Restart the server and reconnect the client after changing groups. engine_status is always available; its available_tools lists exposed tools, while capabilities describe runtime support. Groups are not user roles or an authorization system.

Reuse a token¶

To retain the current App’s generated token, run this while it is still running, in the shell that will launch its next instance:

export KANGENGINE_MCP_TOKEN="$(python -m kangengine.adapters.mcp token)"

Close the old App, then launch serve from that shell. Supplied tokens require at least 32 printable ASCII characters without spaces; use a generated token rather than a password. Store it privately if it must survive shell restarts.

To generate a new token, run unset KANGENGINE_MCP_TOKEN in the App-launching shell before restarting the App, then refresh the client’s credential and restart the client or its IDE host process.

Client configuration output¶

print-config prints settings for the selected App without revealing its token or editing client configuration. On the default port, its JSON output is:

{
  "transport": "streamable-http",
  "url": "http://127.0.0.1:8765/mcp",
  "headers": {
    "Authorization": "Bearer <token>"
  },
  "token_command": "python -m kangengine.adapters.mcp token"
}

Replace <token> with the output of the token command. With --format codex:

[mcp_servers.kangengine]
url = "http://127.0.0.1:8765/mcp"
bearer_token_env_var = "KANGENGINE_MCP_TOKEN"

See the official Codex MCP guide for client configuration.

job_id

Return a completed job’s retained PNG without rendering again.

Matrices are serialized by rows; positions use scene units and the reported up axis. meters_per_unit is null. Resource-only prims have no transforms; ExternalBuffer matrices describe the batch owner, not individual instances. Large geometry, texture and tensor buffers are omitted.

PNGs contain the postprocessed RGB scene with a top-left origin and no UI, at the presented framebuffer’s dimensions. They are returned to the client and saved only when requested. Cancellation cannot undo a file commit already in progress; App shutdown waits for it to finish.

The App must keep rendering to answer requests. Capture and large queries can increase frame time. Profiler enabled and data_status distinguish disabled, empty and retained results; unavailable timings are null without waiting for the GPU.

Authored materials remain retained until the App closes, including after object deletion, and count toward the limits.

Transform edge cases¶

Translation-only edits preserve shear/reflection. Changing only rotation or only scale requires a nonsingular, non-reflected TRS matrix; otherwise supply both to replace the linear part.

Common response fields¶

Fields below describe successful responses; documentation tools do not carry an App session ID. Frame IDs are zero-based native frame indices, comparable only within the same app_session_id, and share the profiler’s frame_index numbering.

Field

Returned by

Meaning

app_session_id

All non-documentation tools

Identifies the App automation session, not the HTTP connection.

frame_id

viewport_capture, scenario_capture; nested in completed scenario job capture metadata

The rendered frame used for the PNG. Retained scenario captures keep their original ID.

observed_before_frame_id

scene_inspect, renderer_profile

Observation was taken before this frame’s updates/render. It does not identify every frame in a profile history result.

processed_before_frame_id

Scene tools except scene_inspect; all camera and recording tools; profile_start/status/result/cancel; scenario_targets/start/status/cancel

Command was processed before this frame’s updates/render. For job queries this is the query boundary, not the job’s measured/captured frame.

last_frame_id

engine_status

Last completed frame at the status observation; null before the first frame.

job_id

profile_start/status/result/cancel, scenario_start/status/cancel

Opaque handle scoped to that job type and App session; invalid after eviction or App restart.

truncated

scene_inspect, resource_inspect, search_docs, get_doc, get_api_docs

Content was omitted due to the query or output bound. Narrow the query or use the tool’s paging controls where available.

next_offset

profile_result

Pass as the next offset; null when no more retained job frames remain.

Ordering edits and captures¶

Wait for an edit’s successful response before calling viewport_capture. Its frame ID is the edit’s processed_before_frame_id or later in the same session. Parallel calls do not guarantee this order. Callbacks and animation may change the scene before capture. Server instructions and the capture tool description also specify this rule.

Errors and recovery¶

Execution errors return is_error=true and {"error": {"code": "...", "message": "..."}}. Protocol/schema errors remain SDK errors. Read message for the specific cause.

Code / symptom

What to do

INVALID_ARGUMENT

Fix inputs; use a new filename and keep output within its allowed directory.

NOT_FOUND

Inspect current paths or job IDs; an old job may have been evicted.

UNSUPPORTED

Check ownership, rendering mode and feature scope. If the guide directory disappeared after startup, use get_api_docs.

NOT_READY

Wait for the first render or job completion.

BUSY

Wait for pending work; finish the active job/recording or respect resource limits.

TIMEOUT

Confirm the App is still producing frames. Check current state before retrying a mutation.

CANCELLED

Request was canceled; inspect current state before retrying.

CLOSED

Start/connect to a running App session.

CAPTURE_FAILED

Check rendering, destination permissions and the App’s error output.

OUTPUT_TOO_LARGE

Request fewer prims/frames/lines or reduce capture resolution.

INTERNAL_ERROR

Inspect the App error and reproduce with a bounded request.

Connection refused / HTTP 401

Check the running App’s URL and current credential using sessions and token.

Multiple session candidates

Select one with --connection-file PATH; unknown process state is not assumed dead.

Missing tool

Check KANGENGINE_MCP_TOOLS and available_tools. Guide search/read tools are omitted without guide files; get_api_docs still works. Restart the server and reconnect after changing groups or installing the guide.

Client blocks deletion

Use the client’s approval workflow; tool annotations are hints, not permission grants.

engine_status may report initializing before the first frame. A hidden GLFW window still requires a display; headless=True is not a displayless renderer.

Stale or ambiguous sessions¶

Automatic selection excludes dead records and requires one remaining candidate; unknown records remain candidates. Use --connection-file PATH if ambiguous. Normal shutdown removes the App’s record; stale records are not automatically deleted.

alive is a process check, not a connection test, and cannot detect PID reuse on macOS. Use status to verify connectivity and the App session ID.
